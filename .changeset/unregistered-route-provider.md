When a route's provider names no registered profile and no fallback provider resolves, the run now fails with a message that says so. With `providers.routes: [{ capability: "chat", provider: "no-such-provider" }]`, the run used to end with a `ConfigurationError` telling you to set `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` / `OPENROUTER_API_KEY`, even when a key was set. The message now reads `No provider client could be resolved: "no-such-provider" is not a known provider. Registered providers: …`, with the registered names sorted. A provider that a plugin registered is listed too. A provider registered with uppercase letters (for example `AcmeAI`) cannot be routed to, because routes look provider names up in lowercase; the message now says that and names the lowercase spelling to register, instead of calling the name unknown while listing it. An alias registered with uppercase letters gets the same message, naming the provider it belongs to. The class (`ConfigurationError`), the code (`provider_unresolved`) and the opening phrase `No provider client could be resolved` are unchanged, and a registered provider with no key still gets the credentials message, word for word. An unregistered provider next to a fallback that resolves still runs on the fallback, as before.
