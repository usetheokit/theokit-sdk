`run.cancel()` on a local run now aborts the provider request. Until now it only set the status to `cancelled`: the LLM request kept streaming, `onDelta` kept receiving updates, and the provider billed the whole generation. The run now aborts the request, stops waiting for in-flight tool calls and passes the abort to custom tool handlers through `ctx.signal`, and delivers no update to `onDelta` once it is terminal. Shell commands and MCP tool calls receive no abort and keep running until they finish. A run cancelled while its MCP servers start up runs no turn, and still closes the MCP clients it owns. A cancelled turn reports no `usage` or `cost`: its result resolves when you cancel, before the turn's usage is collected. A `BudgetTracker` receives no tokens for a cancelled turn either, although the provider bills what it generated before the abort. A failed `close()` of a run-owned MCP client is now reported as a diagnostic naming the server, where it used to be dropped.
